ARP и ответы установленных соединений разрешены. Чужие мосты пропускаются без фильтрации этой таблицей. Остальной трафик проектных мостов учитывается DROP-счётчиком и логируется с ограничением частоты. Worker → PostgreSQL/Redis не имеет прямого маршрута: это сегментация, а не доказательство срабатывания DROP.

Границы доверия и потеря связи

Frontend получает внешние HTTP-запросы, но не имеет прямого доступа к данным. API проверяет доменные права и обращается к хранилищам; worker получает только события. Сетевая доступность не заменяет авторизацию конкретного игрового действия.

Если firewall блокирует API → PostgreSQL, процесс API остаётся живым, но readiness и запросы, которым нужна БД, возвращают 503. Чтение из ещё доступного кеша может продолжиться. PostgreSQL при этом может быть исправен: причина отказа — потеря необходимой связи. После снятия блокировки клиент БД восстанавливает соединение.

Проектная политика применяется отдельно через infra/firewall/firewall.sh. Скрипт заменяет или удаляет только таблицу bridge mini_checkers, сохраняя правила Docker и других приложений. После перезагрузки хоста политику нужно применить заново.

Прикладные ограничения доступа

Токен игрока — 32 случайных байта; в БД хранится SHA-256, в запросе — X-Player-Token. Размер тела ограничен 1 КиБ.
