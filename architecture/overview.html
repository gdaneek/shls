Архитектура и компоненты

Mini Checkers — веб-приложение для игры в шашки вдвоём. API сохраняет состояние партии, Redis ускоряет чтение, а отдельный worker обрабатывает игровые события асинхронно.

C1: контекст

Игрок получает секретный токен своей стороны; зритель читает партию по ID. Регистрации пользователей нет. Браузер и HTTP-клиент используют один API.

C2: контейнеры

Компонент

Ответственность

frontend

Nginx отдаёт HTML/CSS/JS и проксирует /api/ в Game API. Единственный опубликованный порт: 127.0.0.1:${API_PORT:-8000}.

game-api

C++20/Drogon: правила, авторизация, SQL, Redis и фоновая публикация событий. Единственный прикладной владелец игровых таблиц.

event-worker

Отдельный C++20-процесс: получает событие, пишет JSON-лог, подтверждает обработку. Не обращается к БД или кешу.

PostgreSQL 17

Источник истины; два узла с отдельными томами, primary и асинхронный standby.

Redis

Восстанавливаемый кеш состояния с TTL.

RabbitMQ

Три узла, реплицированная quorum-очередь событий.

В обычном стеке девять контейнеров. postgres-maintenance из профиля tools запускается отдельно для обслуживания БД. API подключается только к выбранному primary; после переключения роли узлов могут поменяться.

Frontend, API и worker запускаются независимо. Обработка события отделена от игрового запроса: остановка worker задерживает логирование, но не запись партии. Общей транзакции между PostgreSQL, Redis и RabbitMQ нет — для доставки используется outbox.

Где реализовано

Путь

Содержимое

frontend/

Интерфейс и Nginx; опрос API раз в 2 с, остановка в скрытой вкладке, задержка повтора до 30 с при ошибке.

src/game-api/main.cc

Клиенты БД/кеша, применение схемы, health, запуск HTTP и publisher.

src/game-api/game_api.cc

Обработчики HTTP и запросы SQL/Redis.

src/game-api/game_rules.cc

Правила без зависимости от HTTP и хранилищ.

src/game-api/event_publisher.cc

Чтение outbox и публикация с confirm.

src/event-worker/main.cc

Consumer, ACK, переподключение и heartbeat.

shls/

Публичные заголовки C++.

infra/

Схема, firewall, репликация и backup.

HTTP-путь использует корутины Drogon; блокирующий AMQP-клиент rabbitmq-c работает в отдельном потоке. CMake закрепляет версии зависимостей, многостадийный Dockerfile отделяет сборку от runtime-образа. Показатели качества и границы гарантий — в уровне обслуживания.
