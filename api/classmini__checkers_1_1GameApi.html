class GameApi

Обрабатывает игровые запросы, чтение кеша и транзакционную запись событий в outbox.

PostgreSQL хранит состояние и события одной атомарной операции. После записи обработчик инвалидирует кеш; публикацию в RabbitMQ выполняет EventPublisher независимо от HTTP-ответа.

Примечание

Объект должен существовать всё время обслуживания зарегистрированных маршрутов: обработчики Drogon сохраняют указатель this.

Public Functions

GameApi(drogon::orm::DbClientPtr db, drogon::nosql::RedisClientPtr redis, int cache_ttl_seconds)

Задаёт клиенты хранилищ и время жизни кеша в секундах.

Примечание

Конструктор не создаёт схему и не регистрирует маршруты.

Параметры:

  • db – [in] Ненулевой клиент PostgreSQL для партий и outbox.

  • redis – [in] Клиент Redis; nullptr отключает кеширование.

  • cache_ttl_seconds – [in] Положительное время жизни записи кеша.

void CreateSchema(const std::string &path)

Применяет файл SQL-схемы; передаёт ошибки чтения и БД вызывающему коду.

Примечание

Выполняет блокирующий запрос; вызывается при запуске до обслуживания HTTP.

Параметры:

path – [in] Путь к непустому SQL-файлу; относительный путь считается от рабочего каталога.

Бросает исключение:

  • std::runtime_error – Если файл не открывается, не читается или пуст.

  • drogon::orm::DrogonDbException – Если выполнение SQL завершилось ошибкой.

void RegisterRoutes()

Регистрирует маршруты создания, присоединения, чтения, хода и завершения партии.

Примечание

Вызывается один раз до запуска приложения Drogon. Внутренние пути начинаются с /games; внешний префикс /api добавляется обратным прокси.

drogon::Task<Response> CreateGame(Request request)

Создаёт ожидающую партию и выдаёт токен белых.

Примечание

Партия, хеш токена и событие game.created записываются атомарно. Исходный токен возвращается клиенту, в БД сохраняется только его хеш.

Параметры:

request – [in] HTTP-запрос; X-Request-Id используется для связи с событием.

Бросает исключение:

std::runtime_error – Если не удалось сгенерировать секретный токен.

Результат:

Задача с JSON-ответом: 201 с game_id, side и player_token; 503 при ошибке PostgreSQL.

drogon::Task<Response> JoinGame(Request request, std::string game_id)

Присоединяет игрока к ожидающей партии и выдаёт токен чёрных.

Примечание

Условное обновление статуса позволяет присоединиться только одному сопернику.

Параметры:

  • request – [in] HTTP-запрос с необязательным X-Request-Id.

  • game_id – [in] UUID партии из маршрута; нормализуется к нижнему регистру.

Бросает исключение:

std::runtime_error – Если не удалось сгенерировать секретный токен.

Результат:

Задача с JSON-ответом: 200 с реквизитами игрока, 404 для неверного или отсутствующего UUID, 409 для не ожидающей партии, 503 при ошибке БД.

drogon::Task<Response> GetGame(Request request, std::string game_id)

Читает партию из кеша, обращаясь к PostgreSQL при промахе или ошибке.

Примечание

Чтение не требует токена. Успешный ответ содержит X-Cache: HIT, MISS или BYPASS. Ошибка Redis не препятствует чтению из PostgreSQL.

Параметры:

  • request – [in] HTTP-запрос; его содержимое этим обработчиком не используется.

  • game_id – [in] UUID партии из маршрута.

Результат:

Задача с JSON-ответом: 200 с состоянием партии, 404 для неверного или отсутствующего UUID, 503 при ошибке чтения БД.

drogon::Task<Response> MakeMove(Request request, std::string game_id)

Проверяет права и сохраняет допустимый ход с оптимистической проверкой версии.

Примечание

Запрос выполняет одно звено боя. Ход, версия партии и события сохраняются атомарно; конкурентное изменение версии даёт 409.

Параметры:

  • request – [in] Запрос с X-Player-Token и JSON-полями from/to — парами [row, col].

  • game_id – [in] UUID партии из маршрута.

Результат:

Задача с JSON-ответом: 200 с новой позицией; 400 при неверном теле, 401/403 при отсутствии или несовпадении токена, 404 для неизвестной партии, 409 при конфликте состояния или очереди, 422 для недопустимого хода, 503 при ошибке БД.

drogon::Task<Response> FinishGame(Request request, std::string game_id)

Проверяет права на сдачу или закрытие ожидающей партии и сохраняет результат.

Примечание

В активной партии победа присуждается сопернику сдавшегося игрока; ожидающая партия закрывается без победителя. Остаток цепочки боя очищается.

Параметры:

  • request – [in] Запрос с X-Player-Token и необязательным X-Request-Id.

  • game_id – [in] UUID партии из маршрута.

Результат:

Задача с JSON-ответом: 200 с завершённой партией, 401/403 при ошибке авторизации, 404 для неверного или отсутствующего UUID, 409 при повторном завершении или конфликте версии, 503 при ошибке БД.

drogon::Task<std::optional<Side>> FindPlayer(const std::string &game_id, const std::string &token)

Определяет сторону игрока по секретному токену; при отсутствии возвращает nullopt.

Примечание

Сопоставление выполняется по SHA-256 токена, а не по открытому секрету.

Параметры:

  • game_id – [in] Проверенный UUID партии.

  • token – [in] Исходный секретный токен из заголовка запроса.

Бросает исключение:

drogon::orm::DrogonDbException – Если запрос к PostgreSQL не выполнен.

Результат:

Задача со стороной игрока либо std::nullopt, если соответствие не найдено.

drogon::Task InvalidateCache(const std::string &game_id)

Удаляет партию из кеша, допуская недоступность Redis.

Примечание

Без клиента Redis сразу завершается. Ошибки удаления журналируются; запись в PostgreSQL не откатывается, старая запись кеша ограничена TTL.

Параметры:

game_id – [in] Нормализованный UUID партии для ключа game:{id}.

Результат:

Задача без значения, завершённая после попытки удаления.
