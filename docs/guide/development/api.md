# Справочник HTTP API

## Адрес и идентификаторы

В таблице указаны **внутренние** пути Game API. При обращении через frontend
на хосте добавьте `/api` перед каждым путём: например, `POST /api/games`.
По умолчанию базовый адрес — `http://127.0.0.1:8000/api`.

ID партии — UUID; некорректный или неизвестный ID приводит к `404`. Чтение
состояния доступно по ID без токена. Запросы хода и завершения требуют
заголовок `X-Player-Token`. Токен выдается при создании/присоединении;
его нельзя передавать в query string.

## Маршруты

| Метод | Внутренний путь | Успех | Назначение |
|---|---|---|---|
| GET | `/hello` | 200 | `{"message":"hello-world"}` |
| GET | `/health/live` | 200 | Процесс отвечает |
| GET | `/health/ready` | 200 / 503 | Доступность PostgreSQL/outbox |
| POST | `/games` | 201 | Создать игру и получить токен белых |
| POST | `/games/{id}/join` | 200 | Присоединиться и получить токен чёрных |
| GET | `/games/{id}` | 200 | Прочитать состояние и `X-Cache` |
| POST | `/games/{id}/moves` | 200 | Выполнить один участок хода |
| POST | `/games/{id}/finish` | 200 | Закрыть ожидающую игру или сдаться |

В ответе create/join поля `game_id`, `side` и `player_token`. На запись
хода принимается JSON:

```json
{"from": [5, 0], "to": [4, 1]}
```

Координаты — целые `[row, col]` от 0 до 7. Один вызов — один обычный ход
или один прыжок; если `capture_from` не `null`, бой продолжается тем же
игроком/фигурой. Завершение и ход возвращают текущее состояние игры.

## Состояние

| Поле | Значение |
|---|---|
| `game_id`, `status`, `version` | UUID, `waiting` / `active` / `finished`, версия состояния |
| `board` | Массив восьми строк по восемь символов `.`, `w`, `b`, `W`, `B` |
| `current_turn`, `winner` | Сторона `white` / `black`; `winner` может быть `null` |
| `rules_version` | Версия формата правил; сейчас `2` |
| `capture_from` | Координаты обязательного продолжения либо `null` |
| `captured_cells` | Побитые клетки незавершённой цепочки |
| `legal_moves` | Массив `{from, to, capture}`; `capture` — клетка или `null` |

`legal_moves` пуст для неактивной партии. `X-Cache: HIT`, `MISS` или
`BYPASS` показывает путь GET через Redis/БД, но не заменяет авторизацию.

## Ошибки и повторы

Ошибки приложения возвращаются JSON-объектом с полем `error`:

| HTTP | Пример причины |
|---|---|
| 400 | Неверный JSON координат хода |
| 401 | Нет токена для хода/завершения |
| 403 | Токен не принадлежит участнику партии |
| 404 | Некорректный или отсутствующий UUID |
| 409 | Не та очередь, неподходящий статус, конфликт версии |
| 413 | Тело запроса превышает лимит |
| 422 | Координаты вне доски, запрещённый ход или обязательное взятие |
| 503 | Временно недоступна БД |

Тело HTTP ограничено 1 КиБ на frontend и API. Ошибки Nginx и самого HTTP-фреймворка
(например, 413) могут иметь другой формат вместо JSON с `error`.
При потере ответа на POST
приложение не гарантирует, что запись не произошла; сначала выполните GET.
Надёжной идемпотентности повторных POST по `Idempotency-Key` в текущем
контракте нет. `X-Request-Id` может использоваться для корреляции логов и
событий, но не является ключом идемпотентности.

`/docs` и Swagger UI автоматически не предоставляются.
