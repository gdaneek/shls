# Игра и HTTP API

## Контракт

В таблице внутренние пути API. С хоста добавьте `/api`: базовый адрес —
`http://127.0.0.1:8000/api`. Nginx убирает этот префикс и обращается к
`game-api:8000`.

| Метод | Путь | Результат |
|---|---|---|
| GET | `/hello` | `200`, `{"message":"hello-world"}` |
| GET | `/health/live` | `200`, процесс отвечает |
| GET | `/health/ready` | `200`, PostgreSQL/outbox доступны; иначе `503` |
| POST | `/games` | `201`, создать партию и получить токен белых |
| POST | `/games/{id}/join` | `200`, занять сторону чёрных |
| GET | `/games/{id}` | `200`, состояние и заголовок `X-Cache` |
| POST | `/games/{id}/moves` | `200`, применить один участок хода |
| POST | `/games/{id}/finish` | `200`, сдаться или закрыть ожидающую партию |

Create/join возвращают `game_id`, `side`, `player_token`. Чтение доступно по
UUID без токена; ход и завершение требуют `X-Player-Token`. Тело хода:

```json
{"from": [5, 0], "to": [4, 1]}
```

Координаты — целые `[row, col]` от 0 до 7. Сервер сам определяет сторону,
проверяет очередь и допустимость хода. Ход и завершение возвращают состояние.

| Поле состояния | Значение |
|---|---|
| `game_id`, `status`, `version` | UUID, `waiting` / `active` / `finished`, версия |
| `board` | Восемь строк по восемь символов: `.`, `w`, `b`, `W`, `B` |
| `current_turn`, `winner` | `white` / `black`; победитель может быть `null` |
| `rules_version` | Формат правил, сейчас `2` |
| `capture_from`, `captured_cells` | Клетка продолжения боя или `null`; побитые клетки цепочки |
| `legal_moves` | Массив `{from, to, capture}`; `capture` — клетка или `null` |

## Правила и состояние клиента

- Белые ходят первыми. Простая шашка ходит вперёд, бьёт в обе стороны;
  дамка ходит и бьёт по свободной диагонали.
- Взятие обязательно. Можно выбрать любую цепочку, но нужно продолжать её
  той же фигурой. Побитые фигуры снимаются в конце цепочки и до этого блокируют путь.
- На последнем ряду шашка сразу становится дамкой, включая середину боя.
- Если у соперника нет ходов, фиксируется победа. Сдача даёт победу сопернику;
  закрытие ожидающей партии оставляет `winner=null`. Часы и правила ничьих отсутствуют.

API отдаёт допустимые ходы; браузер лишь подсвечивает их. Токен хранится в
`sessionStorage` вкладки. Клиент игнорирует более старую версию партии и
блокирует ход при неподтверждённом состоянии после сетевой ошибки.

## Ошибки и повторы

| HTTP | Причина |
|---|---|
| 400 | Неверный JSON координат |
| 401 / 403 | Нет токена / токен не принадлежит игроку |
| 404 | Некорректный или отсутствующий UUID |
| 409 | Неверный статус, очередь или конфликт версии |
| 413 | Тело запроса больше 1 КиБ |
| 422 | Координаты вне доски или запрещённый ход |
| 503 | БД недоступна |

Ошибки обработчиков имеют поле `error`; Nginx и HTTP-фреймворк могут вернуть
другой формат. `Idempotency-Key` не реализован: после потери ответа на POST
нужно прочитать состояние, поскольку запись могла состояться. Браузер и
Nginx не повторяют POST автоматически. `X-Request-Id` связывает запись и
событие, но не обеспечивает идемпотентность. Swagger UI не предоставляется.
