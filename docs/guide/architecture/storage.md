# PostgreSQL и кеш

## Схема и владение данными

Game API применяет `infra/postgres/schema.sql` при запуске. Один `DO`-блок
атомарно создаёт таблицы и обновляет старую схему; повторное применение
допустимо. В образе путь задан через `POSTGRES_SCHEMA_FILE`.

```{graphviz} ../_static/data-model.dot
:alt: Таблицы games, game_players, moves и outbox_events
```

| Таблица | Назначение |
|---|---|
| `games` | Доска, статус, очередь, победитель, версия и незаконченная цепочка взятий. |
| `game_players` | Сторона и SHA-256 токена; максимум два игрока на партию. |
| `moves` | История участков хода: координаты 0–63, жертва, превращение. |
| `outbox_events` | События, ожидающие подтверждения брокером. |

Доска хранится строкой из 64 символов. Каждый прыжок цепочки — отдельная
строка `moves` и новая версия игры. Продолжение сохраняется в `capture_from`
и `captured_cells`, поэтому переживает рестарт API.

Приложение выполняет все основные операции SQL:
**INSERT** — создание игры, игрока, хода и события; **SELECT** — чтение и
авторизация; **UPDATE** — изменение партии; **DELETE** — удаление доставленного
outbox-события. Удаление партии через публичный API не предусмотрено.

## Атомарная запись

Изменение партии, ход и событие фиксируются одним SQL CTE. При ходе и
завершении `WHERE version = ...` защищает от конкурентной записи: один запрос
меняет версию, другой получает `409`. Join занимает сторону только при
`status='waiting'`. Ошибка SQL не оставляет частично выполненного изменения.

После коммита API инвалидирует кеш, а publisher доставляет
[событие из outbox](events.md). SQL-транзакция не охватывает Redis и RabbitMQ.

## Cache-aside

```{graphviz} ../_static/read-flow.dot
:alt: Попадание в Redis, заполнение при промахе и обход недоступного кеша
```

Ключ — `game:{uuid}` в нижнем регистре, TTL в Compose — **60 с**.
`X-Cache` показывает путь чтения:

| Значение | Поведение |
|---|---|
| `HIT` | Возврат кеша с `rules_version=2`. |
| `MISS` | Нет актуальной записи: чтение PostgreSQL и попытка заполнить Redis. |
| `BYPASS` | Ошибка Redis или отключённый клиент: чтение PostgreSQL без кеша. |

Redis не сохраняется на диск. Ошибка заполнения/инвалидации не откатывает
успешную запись БД. TTL и повторная инвалидация publisher уменьшают устаревание,
но гонка чтения и записи всё ещё возможна. PostgreSQL остаётся источником истины;
при [promotion](reliability.md) очищаются только ключи `game:*`.
