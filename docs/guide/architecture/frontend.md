# Frontend и взаимодействие с API

## Файлы и точка входа

- `frontend/index.html` — структура страницы и элементы управления.
- `frontend/style.css` — представление доски и интерфейса.
- `frontend/app.js` — состояние вкладки, действия, запросы и опрос.
- `frontend/nginx.conf` и `frontend/Dockerfile` — отдача файлов и proxy.

В браузере нет отдельного фреймворка: это HTML, CSS и JavaScript. Nginx
запущен от непривилегированного пользователя в отдельном контейнере.
Compose публикует его порт 8080 на `127.0.0.1:${API_PORT:-8000}`.
Запрос `/api/games/...` Nginx переписывает в `/games/...` и передаёт
`game-api:8000`. Разрешение Docker DNS выполняется повторно, чтобы frontend
мог найти API после пересоздания контейнера. `/hello` также проксируется для
совместимости; обычный путь проверки с хоста — `/api/hello`.

Nginx ограничивает тело запроса размером 1 КиБ, выставляет CSP, `nosniff`,
`no-referrer` и запрещает кеширование страницы. Повтор запроса proxy при
ошибке отключён: повторный POST мог бы повторить уже выполненное действие.

## Состояние вкладки

`app.js` хранит текущую игру, игрока, выделенную клетку и признаки `busy` /
`stale` в памяти. ID открытой игры и пару `{side, player_token}` для каждой
игры он сохраняет в `sessionStorage` своей вкладки. После перезагрузки он
пытается восстановить открытый ID и ключ; если хранилище недоступно, выводит
предупреждение. Это не серверная сессия и не долговременное восстановление
ключа после закрытия вкладки.

Перед показом состояние проверяется: UUID, восемь строк доски, допустимые
символы, статус, версия, координаты и `legal_moves`. Более старая версия
уже открытой партии не заменяет более новую. Сервер вычисляет допустимые
ходы; frontend только подсвечивает их и отправляет выбранные координаты.

## Polling и действия

Обычный интервал GET — 2 секунды. Одновременно разрешён только один запрос
опроса; пользовательское действие дожидается текущего GET, чтобы оно не
пересекалось с обновлением или сменой партии. В скрытой вкладке опрос
останавливается, при возвращении сразу пробуется GET. В `finished` polling
останавливается.

После ошибки состояние помечается устаревшим, выбор хода сбрасывается,
интервал повтора растёт до 30 секунд. Успешное чтение возвращает обычный
интервал. Таймаут браузерного запроса — 12 секунд. Для неудачного POST
пользователь получает предупреждение, что действие могло выполниться;
перед повтором нужно прочитать игру. Это важно, поскольку полноценный
`Idempotency-Key` для ходов не реализован.

Токен добавляется в `X-Player-Token` только для изменения хода и завершения.
Тело запроса содержит координаты, не доску и не сторону игрока. В HTTP-записи
нет обещания шифрования: защищать соединение при удалённом доступе нужно
отдельно.
