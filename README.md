# Mini Checkers

Mini Checkers — небольшой онлайн-сервис для игры в шашки вдвоём. Реализованы создание игры, подключение второго игрока, ходы, обязательные взятия, дамки и сохранение состояния партии. Основная цель — демонстрация взаимодействия микросервисов и практик безопасной разработки.

Веб-интерфейс на HTML/CSS/JavaScript, REST API на C++20/Drogon и отдельный обработчик игровых событий. PostgreSQL хранит состояние игр, Redis кеширует данные, RabbitMQ передаёт события. Запуск — Docker Compose; настроены сегментация и firewall, перезапуск сервисов, отложенная доставка событий и ежедневные резервные копии БД.

## Запуск

Нужны Docker Engine и Docker Compose v2. Из корня репозитория:

В `.env` задайте пароли; для `POSTGRES_REPLICATION_PASSWORD` используйте вывод
`openssl rand -hex 32` (64 hex-символа). На существующем проекте тома не удаляйте.

```bash
cp .env.example .env    # если .env ещё нет; задайте свои пароли
infrastructure/firewall/firewall.sh apply    # Linux, нужен sudo для nft
docker compose up --build --wait --wait-timeout 180
curl http://127.0.0.1:8000/api/hello    # {"message":"hello-world"}
bash scripts/test-startup.sh
bash scripts/test-integration.sh    # нужен jq; перезапускает event-worker и redis
bash scripts/test-network.sh        # сегментация и firewall
```

Откройте **http://127.0.0.1:8000/**. Порт сайта задаётся `API_PORT` в `.env`; API доступен через `/api/` на том же адресе. Backend и инфраструктура напрямую наружу не опубликованы. Остановка — `docker compose down`, удаление данных вместе с томами — `docker compose down -v`.

## Как играть

1. Нажмите **«Создать игру»** — вы играете белыми. Скопируйте ID партии.
2. Нажмите **«Вторая вкладка»**, вставьте ID и выберите **«Присоединиться»** — это чёрные. Для игры с другим человеком передайте ему ID; сайт по умолчанию доступен только с вашего компьютера.
3. Выберите шашку и затем подсвеченную клетку. Подключение соперника и ходы появляются автоматически: доска обновляется раз в 2 секунды. Кнопка **«Обновить»** остаётся для ручного запроса.
4. **«Сдаться»** завершает партию. **«Смотреть»** открывает игру без занятия места.

Ключ игрока хранится только в своей вкладке и переживает её перезагрузку. Не закрывайте вкладку до конца игры; для второго игрока используйте «Вторая вкладка», а не дублирование первой.

Взятие обязательно в обе стороны. Продолжайте бой той же шашкой, пока есть взятия. На последнем ряду шашка становится дамкой (Д), в том числе во время боя; дамка ходит и бьёт по всей диагонали. Побитые фигуры отмечаются крестиком и снимаются после всей цепочки. Победа определяется автоматически, когда у соперника нет фигур или ходов. Часы и спортивные правила ничьих не реализованы.

В скрытой вкладке автообновление приостанавливается, при возвращении возобновляется. После завершения партии оно останавливается.

Если VPN блокирует доступ к сайту, разрешите локальную сеть в его настройках или временно отключите VPN.

## Сеть и firewall

| Сегмент | Подсеть | Мост | Сервисы |
|---|---|---|---|
| `public` | `10.10.1.0/24` | `mc-public` | game-api `.2`, frontend `.3` (сайт опубликован на `127.0.0.1:8000`) |
| `data` (internal) | `10.10.2.0/24` | `mc-data` | game-api `.2`, postgres `.3`, redis `.4`, postgres-standby `.5` |
| `messaging` (internal) | `10.10.3.0/24` | `mc-msg` | game-api `.2`, rabbitmq `.3`, event-worker `.4` |

Между внутренними сегментами маршрута нет. Трафик между контейнерами фильтрует таблица nftables `bridge mini_checkers` ([`infrastructure/firewall/mini-checkers.nft`](infrastructure/firewall/mini-checkers.nft)): разрешены frontend → game-api:8000, game-api → оба узла PostgreSQL:5432, game-api → redis:6379, game-api → rabbitmq:5672 и event-worker → rabbitmq:5672. Узлы PostgreSQL общаются друг с другом по 5432; служебный job профиля `tools` (`.6`) имеет доступ только к ним. Остальное логируется (`mc-fw-drop:`) и отбрасывается. Управление: `infrastructure/firewall/firewall.sh apply|rollback|status`. Правила не сохраняются после перезагрузки хоста — их нужно применить заново, лучше до `docker compose up`.

## API

Пути ниже указаны относительно `/api`: например, `POST /api/games`.

| Метод и путь | Назначение |
|---|---|
| `POST /games` | Создать игру; в ответе `game_id` и токен белых |
| `POST /games/{id}/join` | Присоединиться вторым игроком; в ответе токен чёрных |
| `GET /games/{id}` | Состояние игры; заголовок `X-Cache: HIT`/`MISS`/`BYPASS` |
| `POST /games/{id}/moves` | Ход `{"from": [5, 0], "to": [4, 1]}` (строка, столбец) |
| `POST /games/{id}/finish` | Завершить игру (сдаться); побеждает соперник |

Ходы и завершение требуют заголовок `X-Player-Token`. Правила упрощены: шашка ходит на одну клетку по диагонали вперёд, белые начинают. После каждого изменения Game API сбрасывает кэш Redis и публикует событие (`game.created`, `player.joined`, `move.made`, `game.finished`) в очередь RabbitMQ `game.events`, которую читает Event Worker:

```bash
docker compose logs -f event-worker
```

## Резервные копии

```bash
scripts/backup.sh                      # создать архив БД в backups/
scripts/restore.sh backups/<имя>.dump   # восстановить в новую тестовую БД
scripts/backup-timer.sh install        # ежедневный бэкап в 02:00, systemd user timer
scripts/backup-timer.sh remove         # отключить расписание
```

Архивы хранятся 7 дней. Восстановление не перезаписывает рабочую БД.

## Переключение PostgreSQL

Имена `postgres` и `postgres-standby` обозначают узлы, а не неизменные роли.
Текущий primary: `scripts/postgres-primary.sh`. Бэкапы автоматически выбирают его.

```bash
scripts/test-postgres-failover.sh   # демо: аварийно завершает primary, меняет роли, возвращает старый узел как standby
```

Переключение управляемое, не автоматическое: для остановленного primary —
`scripts/promote-postgres.sh <живой-standby>`, затем
`scripts/rejoin-postgres.sh <старый-primary>`. Скрипт сохраняет адрес в `.env`
и пересоздаёт API. Не запускайте старый primary обычным `start` до rejoin.
Перед rewind сохраняется физический архив в `backups/`.
Репликация асинхронная: последние ещё не переданные транзакции при аварии
могут потеряться; демо запускайте без параллельных записей. Общий хост остаётся
единой точкой отказа.
